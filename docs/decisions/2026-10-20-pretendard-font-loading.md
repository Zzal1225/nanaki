# Pretendard 글꼴 불러오기 방식

- 날짜: 2026-10-20
- 관련: PR #4

## 상황

본문 글꼴로 Pretendard를 쓴다. 한글 글꼴은 글자 수가 많아서 가변 글꼴 전체 파일(`PretendardVariable.woff2`)이 약 2MB다.
nanaki는 모바일 성능(Lighthouse)과 오프라인 우선을 증명해야 하는 앱이라, 첫 화면에서 받는 크기와 오프라인 동작을 둘 다 고려해야 했다.

## 결정

`pretendard` npm 패키지의 **동적 서브셋** CSS(`pretendardvariable-dynamic-subset.css`)를 `src/app/layout.tsx`에서 import한다.

- 동적 서브셋은 글자를 92개 조각으로 나누고 `unicode-range`로 지정해서, 브라우저가 화면에 나온 글자가 든 조각만 받는다.
- 빌드하면 Next(Turbopack)가 92개 조각을 `_next/static/media`로 복사하고 CSS 경로를 바꿔서, 글꼴이 우리 도메인에서 제공된다.

## 대안과 버린 이유

| 대안                                  | 버린 이유                                                                                                                               |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| CDN 링크 (jsDelivr, 시안이 쓰는 방식) | 외부 서버에 의존한다(연결 추가, CDN 장애 영향). 다른 도메인이라 오프라인 캐시가 번거롭고, 오프라인 우선 원칙과 맞지 않는다.             |
| `next/font/local` + 전체 파일 1개     | Next 공식 방식이고 새 라이브러리가 없지만, 조각을 나눠 받는 방식을 지원하지 않아 2MB를 처음에 전부 받아야 한다. 모바일 성능에 불리하다. |

## 결과

- 빌드 결과에 글꼴 조각 92개가 포함되고, 첫 조각은 같은 도메인에서 `200 font/woff2`(약 34KB)로 내려온다.
- Vercel 배포의 `/design-system`에서 Network 탭을 보면 92개 중 10여 개 조각만 받는다.

## 감수한 것

- `node_modules`가 약 98MB 늘었다. 사용자에게 보내는 앱 크기와는 무관하고, 설치와 CI가 조금 느려진다.
- `next/font`의 대체 글꼴 크기 보정(글꼴이 바뀔 때 레이아웃 흔들림 줄이기)은 쓰지 못한다. CSS의 `font-display: swap`으로 글꼴이 오기 전에는 시스템 글꼴로 먼저 보여 준다.
- 실제 오프라인 캐시는 step2 PWA(Serwist) 작업에서 이어 한다.
