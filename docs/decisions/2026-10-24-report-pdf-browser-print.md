# 보고서 PDF는 라이브러리 없이 브라우저 인쇄로

> 2026-10-24 · 40 보고서

## 상황

기간을 골라 타입별 요약(가계부 분류, 운동 시간, 체중 변화 등)을 보고, PDF로 저장하고 싶다. 앱은 PWA이고 첫 로딩 JS 용량을 계속 줄이고 있었다. 기록은 기기 사본으로만 계산한다.

## 결정

"PDF로 저장" 버튼 = `window.print()`. 인쇄용 CSS로 A4 한 장 모양을 만든다.

- `@page { size: A4 }`, `@media print`에서 앱 틀(사이드바·하단 탭·+ 버튼)을 숨기고 보고서 칸만 남긴다.
- 인쇄하는 동안만 라이트 테마로 바꿔 흰 종이에 맞춘다.
- 화면과 인쇄가 **같은 컴포넌트**다. 인쇄 전용 머리(로고·기간·만든 날)·요약 숫자 줄·꼬리만 `hidden print:*`로 인쇄에만 보인다.
- 사진은 넣지 않는다(몸 사진은 보고서에 넣지 않는 원칙, 후기 사진도 함께 뺌).

## 대안과 버린 이유

- **jsPDF / react-pdf**: 수백 KB 라이브러리 추가, 화면과 별도로 PDF 레이아웃을 한 번 더 만들어야 한다.
- **html2canvas + jsPDF**: 화면을 그림으로 찍어 넣어 글자가 흐리고 검색·복사가 안 된다. 다크 모드·글꼴 로딩 타이밍 문제도 있다.
- **서버에서 PDF 생성(헤드리스 브라우저)**: 무료 등급 서버리스에서 무겁고, 기록 내용을 서버로 보내야 한다(지금은 기기 사본으로만 계산).

## 결과

- 추가 라이브러리 0. 글자가 선명한 벡터 PDF. 오프라인에서도 만들 수 있다.
- 인쇄 모양은 E2E가 `emulateMedia({ media: 'print' })`로 확인한다(하단 탭이 사라지는지).

## 감수한 것

- 파일 이름·쪽 나눔을 앱이 완전히 정하지 못한다(브라우저 인쇄 창 설정을 따른다).
- 아이폰은 "PDF로 저장" 대신 인쇄 → 공유 → 파일에 저장으로 한 단계 더 거친다.
- 빌드 도구가 인쇄 CSS를 바꾸는 문제를 겪었다: `@page`를 `@media print` 안에 두었더니 빌드가 그 묶음을 통째로 버렸다. 화면은 멀쩡해 보여 늦게 알아챘고, `@page`를 밖으로 옮긴 뒤 인쇄 모양을 E2E로 따로 보게 했다.
- 인쇄 CSS가 "보고서 화면이 DOM에 있을 때"를 `body:has()`로 골랐다가, 떠난 화면이 숨은 채 남는 문제에 걸려 body 클래스 방식으로 바꿨다 ([트러블슈팅](../troubleshooting/2026-10-24-hidden-routes.md)).
