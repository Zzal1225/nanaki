# 테스트 전략: 자동화할 것과 아이폰에서만 확인할 것을 나누기

> 2026-10-22 · step2 마무리 아이폰 확인 뒤

## 상황

step2를 마치고 아이폰에서 직접 써 보니 문제가 6건 나왔다: 다시 연 화면이 튕김, 오프라인 로그아웃, 입력칸을 누르면 화면 확대, 키보드 위에 하단 탭, 상단 글자가 상태 표시줄과 겹침, 구름 아이콘.

분석해 보니 **3건은 이미 있던 Playwright·크롬으로 잡을 수 있었다.** 못 잡은 이유는 테스트 방식이었다.

- E2E가 화면을 `page.goto`로 매번 새로 열어서, **화면을 오갈 때만** 생기는 문제를 지나쳤다.
- 실패 상태(서버 오류·저장 거절)는 mock을 쓴 단위 테스트로만 봤다.
- 기능 흐름 E2E가 모두 PC 1280px이었다.

## 결정

1. **아이폰 크기·터치 E2E 프로젝트(크로미움)**: 앱 안을 눌러 이동하고, 화면마다 입력칸 글자 16px 이상(확대 방지)·가로 넘침·터치 영역 44px을 자동으로 검사한다.
2. **실기기 체크리스트**: 자동화할 수 없는 것만(상태 표시줄·홈 막대, 실제 키보드, 홈 화면 앱 로그인, 서비스 워커) 약 10분 분량으로. 레이아웃·입력·서비스 워커·로그인을 건드린 PR 뒤와 step 마무리 때만 본다.
3. 이어서: 실패 상태 E2E(Playwright `route`로 서버 응답을 바꿈) → WebKit E2E(처음엔 경고만). 기능별 E2E 확대는 천천히.

## 대안과 버린 이유

- **실기기 클라우드(BrowserStack 등)**: 진짜 iOS지만 새 도구·유료. 지금 규모에 과하다.
- **safe-area를 CDP로 흉내**: 흉내가 맞는지 확인할 방법이 없는 추측이라 체크리스트로 넘겼다.
- **MSW 도입**: E2E는 Playwright `route`로, 단위는 저장소 함수 mock으로 충분했다.
- **모든 PR마다 실기기 확인**: 손이 많이 들어 지속하지 못한다(직접 겪음). 몰아서 본다.

## 결과

- 처음 돌린 자동 검사에서 터치 영역 위반 2곳(설정 스위치 26px, 루틴 선택 버튼 34px)을 실기기 없이 찾아 고쳤다.
- 이후 "화면을 오갈 때만 생기는" 문제가 두 번 더 있었고(숨은 화면의 redirect, 로그인 바탕색), 둘 다 앱 안을 눌러 이동하는 E2E에 회귀 확인을 넣었다 ([트러블슈팅](../troubleshooting/2026-10-24-hidden-routes.md)).
- 실기기 확인은 PR마다가 아니라 몰아서 하고, 결과는 체크리스트와 마일스톤에 기록한다.
- 이후(2026-10-26): WebKit E2E는 최근 CI 50회 실행이 모두 통과한 것을 근거로 경고에서 **실패(병합 막기)**로 바꿨다. 화면 비교 허용치를 0으로 다시 재 보다가 낡은 기준 이미지 24장이 그동안 통과하고 있던 것을 찾아, 새로 찍고 허용치를 전체의 0.2%에서 10픽셀로 줄였다.
- 셈해 보니(#76 ~ 2026-10-26) 아이폰에서 나온 버그 17건 중 11건은 기기에서만 확인할 수 있는 종류(홈 화면 앱, 실제 키보드, 카메라, 파일 선택, 인쇄)였고, 자동 테스트가 기기 확인 전에 잡은 실제 버그는 4건이었다. 16px·가로 넘침·44px 검사에 걸릴 종류는 #76 이후 기기에서 한 건도 나오지 않았다 ([milestones.md](../milestones.md)).

## 감수한 것

- WebKit E2E는 리눅스의 WebKit이라 아이폰 사파리와 같지 않다. 홈 화면 앱·실제 키보드처럼 기기에서만 생기는 문제는 여전히 사람이 본다.
- 상태 표시줄·키보드의 실제 모습은 사람이 본다.
