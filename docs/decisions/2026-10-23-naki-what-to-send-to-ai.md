# AI 챗봇 나키: 무엇을 AI에 보내고 무엇을 기기에서 할지

> 2026-10-23 · 34a(제공자·구조), 이어서 사용자가 만든 이름 보내기

## 상황

"지난달 외식비 얼마였지?" 같은 자연어 질문을 기록 검색 조건으로 바꿔야 한다. 조건은 무료 등급으로 돌아가야 하고, **기록 내용(금액·메모·제목·날짜·건수)은 AI에 보내지 않는다**는 기획 원칙이 있다.

## 결정

### 구조: AI는 조건만, 찾기·계산은 앱이

- 제공자: Gemini 무료 등급 + Vercel AI SDK(`ai`, `@ai-sdk/google`). 호출은 Next.js Route Handler에서, **어댑터 파일 하나**로 감싸고 다른 파일의 SDK import는 ESLint로 막는다.
- AI에 보내는 것: 질문 문장 + 필드 정의(칸 이름·종류·기본 선택지) + 오늘 날짜.
- AI가 돌려주는 것: 조건 JSON. Zod로 검증해 허용된 타입·칸·연산자만 남기고, **검색 화면과 같은 길(기기 사본)**로 찾는다. 합계·건수·평균·최고·최저도 기기에서 계산한다.
- 하루 횟수는 DB 함수가 센다(로그인 계정·체험 계정·서비스 전체 한도).

### 추가 결정: 사용자가 만든 분류·태그 이름은 보낸다

AI는 기본 선택지만 알아서 사용자가 직접 만든 분류("Ott")를 몰랐다. "모르는 말은 검색어로" 피하는 방법도 써 봤지만, 같은 말이 제목·메모에 있으면 섞여 칸 조건으로 정확히 잡지 못했다.

→ **이름 문자열만** 보낸다: 선택 칸의 직접 입력값과 태그, 각각 최대 50개, 사용 횟수 없이. 기록 내용은 계속 보내지 않는다. 나키 화면 안내 문구에 이 사실을 적는다.

## 대안과 버린 이유

### 제공자·구조

- **Groq(Llama)**: 무료지만 한국어 품질이 조금 떨어졌다. **OpenRouter 무료 모델**: 안정성이 들쭉날쭉. **Claude·OpenAI**: API 무료 등급이 없다.
- **업체 SDK 직접 호출**: 제공자를 바꾸면 호출 코드가 다 바뀐다. AI SDK는 import 한 줄 + Zod 검증 내장.
- **서버에서 RLS로 조회·집계**: 검색과 다른 조회 코드가 하나 더 생기고, 아직 서버에 안 보낸(오프라인) 기록이 빠져 "기록 탭에서 보기"와 건수가 어긋날 수 있다.
- **결과 전체 목록**: 질문을 여러 번 하면 대화 화면이 길어진다 → 3개 + "기록 탭에서 보기".

### 사용자가 만든 이름

- **계속 안 보냄**: 개인정보는 가장 적지만 AI가 추측만 한다.
- **기록 내용까지 보냄(요약 등)**: 정확도는 높지만 "데이터는 안 보내고 계산은 기기에서" 원칙이 무너진다.

## 결과

- 모델 선택(실제 키로 측정): 큰 모델은 응답에 수십 초가 걸려 채팅에 쓸 수 없었고, lite 모델이 약 1초로 같은 조건을 만들었다 → 기본값. 모델 이름은 환경 변수로 바꿀 수 있다.
- 이름을 보낸 뒤: "내가 구독중인 Ott는?" → 분류 Ott 칸 조건. 종목(클라이밍)·태그(회사)도 정확히 잡는다.
- 답변마다 AI가 만든 조건을 칩으로 보여 줘 사용자가 확인하고, 같은 조건으로 검색 화면에 넘어갈 수 있다.

## 감수한 것

- 무료 등급의 한도·모델 이름이 자주 바뀐다 → 모델을 환경 변수로, 하루 횟수 제한.
- 날짜 계산("지난달")을 AI에 맡긴다 → 오늘·주 시작 요일을 지시문에 넣고, 받은 날짜는 유효성만 검사한다.
- lite 모델은 애매한 질문에 약할 수 있다 → 조건 칩으로 사용자가 확인한다.
- 분류·태그 이름 자체가 민감할 수 있다(예: "병원") → 안내 문구로 알리고, 개인정보처리방침이 생기면 같은 문장을 넣는다.
