# 성능 측정

바꾸기 전에 먼저 재고, 같은 조건으로 다시 재서 전후를 비교합니다. 직접 측정한 값만 적습니다.

## 측정 환경 (Lighthouse CI)

| 항목     | 값                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 어디서   | GitHub Actions `integration` 작업 (ubuntu-latest)                                                         |
| 무엇을   | 테스트용 로컬 Supabase에 붙인 production 빌드(`next start`)                                               |
| 도구     | Lighthouse 13.5.0 (Node API), 크롬 156 (Playwright Chromium)                                              |
| 모드     | 모바일, simulate 스로틀링 (Lighthouse 기본)                                                               |
| 상태     | 매 측정 전 브라우저 캐시를 비움(첫 방문). 쿠키는 유지(로그인 뒤 화면)                                     |
| 데이터   | 체험하기 예시 기록 12개                                                                                   |
| 횟수     | 화면마다 3회, 성능 점수 가운데 실행의 값                                                                  |
| 스크립트 | [`scripts/lighthouse.mts`](../scripts/lighthouse.mts), 기준은 [`lighthouserc.json`](../lighthouserc.json) |

> step1 마무리 때 배포 주소(Vercel)의 로그인 화면을 Lighthouse CLI 12.8로 잰 값([milestones](milestones.md))과는 서버·네트워크·Lighthouse 버전이 달라 서로 비교하지 않습니다. 전후 비교는 이 표끼리만 합니다.

### 눈에 띄는 점 (아직 원인을 확인하지 않은 가설)

- 홈·기록 탭은 FCP(첫 그림)는 2초 안팎인데 LCP(가장 큰 요소)가 5~6초다. 화면 틀이 먼저 그려지고, 기록은 브라우저에서 JS가 실행된 뒤 Supabase에서 받아 그리는 구조라 그 사이가 벌어지는 것으로 보인다.
- 로그인 뒤 화면의 JS 전송량이 400KiB 안팎이다.
- 개선은 step2 26단계에서 원인을 확인한 뒤 하고, 같은 조건으로 다시 재서 이 표 아래에 전후를 적는다.
