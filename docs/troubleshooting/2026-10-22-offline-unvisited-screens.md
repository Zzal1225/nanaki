# 연 적 없는 화면을 오프라인에서 열기 — CI 다섯 번 실패의 원인들

> 2026-10-22 · PR #70 · 기록 상세 주소를 `/records/<id>`에서 `/records/view?id=<id>`로 바꾼 이유

## 문제

오프라인 우선 설계의 목표 중 하나는 "**한 번도 연 적 없는 화면**도 오프라인에서 열린다"였다. 기록 상세·수정·타입 상세·작성 화면을 서비스 워커가 미리 받아 두면 될 줄 알았는데, E2E가 다섯 번 연속 실패했다. 원인이 매번 달랐다.

## 원인과 해결 (순서대로)

### 1. 설계: 경로에 id가 있으면 HTML 한 장으로 다른 기록을 열 수 없다

기록 상세 HTML 한 장(가장 작은 UUID 주소로 받아 둔 것)을 다른 기록 주소에 쓰면 화면이 "기록을 여는 중"에서 멈췄다. 경로 세그먼트 값(`[id]`)이 HTML 안의 라우터 정보에 남아 실제 주소와 어긋났기 때문이다.

→ 주소를 **`/records/view?id=<id>`**로 바꿨다(사용자 승인). `?` 뒤의 값은 HTML에 들어가지 않아 화면 HTML이 기록과 상관없이 한 장이 되고, 브라우저가 `useSearchParams`로 id를 읽는다. 예전 주소는 redirect로 넘긴다.

### 2. 앱: "이미 받았나" 확인이 엉뚱한 것을 찾았다

미리 받기가 `caches.match(url, { ignoreSearch: true })`로 "이미 있나"를 봤는데, Next가 받아 둔 `/records?_rsc=…` 조각(화면 일부 데이터)이 맞아서 **아무것도 받지 않았다**. 실패 지점에서 Cache Storage 목록을 찍어 보니 방문한 두 화면만 있었다.

→ 주소 그대로 찾고, 페이지에서 직접 `fetch`한다.

### 3. 테스트: 통과했지만 아무것도 확인하지 않았다

`page.waitForFunction(async () => …)`이 Promise 자체를 참으로 보고 바로 통과했다. 그래서 미리 받기가 끝나기 전에 오프라인으로 바꿨다.

→ `expect.poll`로 바꿨다.

### 4. 작업 실수

`git add`에 지운 폴더 경로를 넣어 add가 통째로 실패한 채 커밋했다. 파일 이동만 들어가고 나머지가 빠졌다. → 다시 커밋.

### 5. 요청 때 그리는 화면(◐)은 저장본으로 열면 멈춘다

타입 상세(`/records/type/[type]`)는 일부를 요청 때 그리는 화면(◐)이었다. 저장본으로 열면 그 부분에서 멈췄다. → `generateStaticParams`로 다섯 타입을 모두 미리 그려 정적(○)으로. 오프라인 작성 테스트가 저장 직후 이동해 저장이 끊기던 것도 홈 이동을 기다리게 고쳤다.

## 결과

- CI E2E 11개 통과: 한 번도 안 연 기록 상세·수정·타입 상세·작성(다른 타입)이 오프라인에서 열리고, 미리 받지 않는 화면은 대체 화면이 나온다.
- 이후 규칙: **오프라인에서 저장본으로 쓸 화면은 정적(○)이어야 하고, 주소의 값은 브라우저가 읽는다.** 서비스 워커가 미리 받는 화면 목록은 한 곳(`OfflineWarmup`)에 둔다.

## 배운 것

- "통과"가 아무것도 확인하지 않은 경우가 두 번(2, 3) 있었다. 의심스러우면 실패 지점의 **실제 상태(캐시 목록)**를 찍어 본다.
- 한 번의 실패에 원인이 하나라고 가정하지 않는다. 하나를 고친 뒤의 다음 실패는 다른 원인일 수 있다.
