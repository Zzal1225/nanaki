# 떠난 화면이 숨은 채 남아 있었다 — Next.js cacheComponents에서 생긴 두 가지 버그

> 2026-10-22 PR #74 (다시 연 화면이 튕김) · 2026-10-24 PR #122 (로그인 뒤 앱 전체가 초록)

Next.js 16의 `cacheComponents`는 떠난 화면을 지우지 않고 **숨긴 채 DOM에 남겨 둔다**(React Activity). 다시 돌아오면 빠르지만, "화면을 떠나면 사라진다"고 가정한 코드가 두 번 깨졌다.

## 1. 작성 화면을 다시 열면 홈으로 튕김 (2026-10-22)

### 문제

아이폰에서 한 타입의 작성 화면에 갔다가 홈으로 돌아와 다른 타입 작성을 누르면 아무 일도 일어나지 않았다(사용자 제보). 배포 주소에서 Playwright(아이폰 13 흉내)로 재현하니 두 번째 메뉴를 누르면 주소가 `/`에 머물렀다. 같은 타입을 다시 눌러도, PC에서도 같았다. 타입 화면(`/records/type/expense`)도 두 번째로 열면 `/records`로 튕겼다.

### 원인을 찾은 방법

1. 메뉴가 안 열리는 줄 알았는데, 메뉴 항목을 찍어 보니 테스트에서 이름을 잘못 적은 것이었다("운동 쓰기" → 실제 "운동 기록").
2. `history.pushState/replaceState`를 감싸 찍었다: `pushState /records/new?type=workout` 바로 뒤에 `replaceState /`가 따라왔다.
3. 서비스 워커를 막아도(`serviceWorkers: 'block'`) 재현 → 서비스 워커 제외.
4. 개발 서버에서 작성 화면에 임시 로그: **닫은 뒤(홈에 있는 동안)에도 작성 화면이 다시 그려지며** `type`을 빈 값으로 읽었다.

### 원인

작성 화면은 "`type`이 없으면 그리는 중 `redirect('/')`"였다. 숨은 화면도 지금 주소(`/`)로 다시 그려지는데, 그때 `type`이 없어 redirect가 던져졌고, 다음에 그 화면이 보일 때 홈으로 옮겨졌다. (redirect 실행이 미뤄지는 세부 동작은 추정이다. Next 내부 코드는 확인하지 않았다.)

### 해결

그리는 중 `redirect()` 대신 effect 안에서 `router.replace`를 부르는 `useReplaceRoute(target)`. 숨은 화면에서는 effect가 돌지 않는다. 작성 화면·타입 화면에 적용하고 규칙으로 남겼다. 같은 재현 스크립트로 작성 3번(가계부 → 운동 → 가계부), 타입 화면 2번 모두 그 화면에 머무는 것을 확인했고, E2E(`revisit-flow.spec.ts`)를 추가했다.

## 2. 로그인 뒤 앱 전체 바탕이 초록 (2026-10-24)

### 문제

로그인 화면에 등장 애니메이션을 넣으며 바탕을 초록으로 바꿨다(PR #121). 배포 뒤 로그인 화면에서 체험하기로 들어가면 **홈·기록 탭까지 앱 전체 바탕이 초록**이었다. 새로 고치면 정상.

### 원인을 찾은 방법

로그인 뒤 페이지에서 `document.querySelector('main.login-screen')`이 여전히 있었다. 새로 고친 뒤에는 없어서, 클라이언트 이동에서만 생기는 문제로 좁혔다. 로그인 화면 하나만 보는 단위·화면 비교 테스트로는 잡히지 않는 종류였다.

### 원인

로그인 화면의 당김 바탕을 초록으로 하려고 `body:has([data-login-screen]) { background: 초록 }`을 썼다. 로그인 뒤에도 숨은 로그인 화면이 DOM에 남아 `:has()`가 계속 맞았다. 보고서 인쇄 CSS의 `body:has([data-print-root])`도 같은 구조였다(보고서를 떠난 뒤 다른 화면을 인쇄하면 빈 종이).

### 해결

화면이 보이는 동안 effect로 `<body>`에 클래스를 붙이고 cleanup에서 떼는 `useBodyClass(name)`. **React는 화면을 숨길 때 effect를 정리**하므로 숨는 순간 클래스가 떨어진다. CSS는 `body.login-screen-body`, `body.report-printing`으로 바꿨다. 로그인 → 홈으로 이동하는 E2E에 "body에 로그인 클래스가 없다" 확인을 더했다.

## 배운 것

- cacheComponents에서는 "떠난 화면은 사라진다"가 성립하지 않는다. **그리는 중의 부수 효과(redirect)와 DOM 존재 여부에 기대는 CSS(:has)** 둘 다 깨진다. 안전한 경계는 effect다(숨으면 정리된다).
- 두 버그 모두 **화면을 오갈 때만** 생겼다. 화면을 주소로 바로 여는(`page.goto`) E2E는 못 잡는다 → 새 E2E는 로그인 화면 말고는 앱 안을 눌러 이동한다는 규칙을 두었다.
