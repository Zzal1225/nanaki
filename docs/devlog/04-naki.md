# AI에 무엇을 보내고 무엇을 기기에서 할지 — "질문과 이름만 보내고, 찾기와 계산은 앱이"

> 2026-10-23 · PR #90 · #94 · #96 · 이어서 #133 · #135 · 기록 내용은 AI에 보내지 않고, 사용자가 만든 분류·태그 **이름만 최대 50개**

## 세 줄 요약

- nanaki의 AI 챗봇 "나키"는 "지난달 외식비 얼마였지?" 같은 질문에 답합니다. 그런데 **기록 내용(금액·메모·제목·날짜·건수)은 AI에 한 글자도 보내지 않습니다.**
- AI가 하는 일은 질문을 **검색 조건**으로 바꾸는 것뿐입니다. 그 조건으로 기록을 찾고 합계를 내는 일은 사용자의 기기 안에서 앱이 합니다.
- 한 가지는 선을 옮겼습니다. 사용자가 직접 만든 분류·태그의 **이름**은 보냅니다. 왜 그랬고 무엇을 감수했는지가 이 글의 내용입니다.

## 무슨 일이 있었나

가계부 앱에 AI를 붙이는 가장 쉬운 방법은 기록을 통째로 AI에 넘기고 "알아서 답해 줘"라고 하는 것입니다. 정확하고 빠르게 만들 수 있습니다. 하지만 사용자의 소비 내역과 메모가 외부 서버로 나갑니다.

nanaki는 처음부터 반대 원칙을 세웠습니다. **데이터는 보내지 않고, 계산은 기기에서.** 여기에 현실 조건이 하나 더 있었습니다. 1인 프로젝트라 AI는 **무료 등급**으로 돌아가야 했습니다.

## 어떻게 나눴나: AI는 통역, 앱은 사서

비유하면 AI는 **통역사**이고 앱은 **도서관 사서**입니다. 사용자가 "지난달 외식비 얼마였지?"라고 물으면 통역사는 그 말을 사서가 알아듣는 요청서로 바꿉니다. "타입: 가계부, 분류: 식비, 기간: 지난달 1일~말일, 합계." 통역사는 서가에 들어가지 않습니다. 책을 찾고 세는 일은 사서가 합니다.

|           | AI(Google Gemini)에게                                          | 기기 안의 앱이                                                         |
| --------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 보내는 것 | 질문 문장, 기록 칸의 정의(칸 이름·종류·기본 선택지), 오늘 날짜 |                                                                        |
| 받는 것   | 검색 조건(정해진 모양의 데이터)                                |                                                                        |
| 하는 일   | 말을 조건으로 바꾸기                                           | 조건 검사 → 기기 안 사본에서 찾기 → 합계·건수·평균 계산 → 답 보여 주기 |

AI가 돌려준 조건은 그대로 믿지 않습니다. **정해진 모양인지 검사**하고, 허용된 타입·칸·비교 방식만 남깁니다. AI가 엉뚱한 칸을 지어내도 걸러집니다. 통과한 조건은 검색 화면이 쓰는 **같은 길**로 기록을 찾습니다. 그래서 나키의 답과 "기록 탭에서 이 조건으로 보기"의 결과가 항상 같습니다.

AI 업체와 맞닿는 코드는 **파일 하나**에만 두고, 다른 파일에서 AI 라이브러리를 불러오면 검사 도구가 막습니다. 업체를 바꾸거나 "무엇을 보내는지" 감사할 때 볼 곳이 한 군데입니다.

## 벽에 부딪힌 것: AI가 "Ott"를 모른다

첫 버전을 써 보니 문제가 있었습니다. "내가 구독 중인 Ott는?"이라고 물으면 AI가 조건을 못 만들었습니다. AI는 **기본 선택지**(식비·교통비 같은)만 알고, 사용자가 직접 만든 분류 "Ott"는 처음 보는 말이었기 때문입니다.

"모르는 말은 검색어로 넘기기"도 해 봤습니다. 그런데 같은 말이 제목이나 메모에도 있으면 섞여서, "분류가 Ott인 기록"을 정확히 잡지 못했습니다.

선택지는 셋이었습니다.

| 선택지                                  | 정확도         | 개인정보                           | 결정     |
| --------------------------------------- | -------------- | ---------------------------------- | -------- |
| 계속 안 보냄                            | AI가 추측만 함 | 가장 적음                          | 버림     |
| 기록 내용까지 보냄 (요약 등)            | 높음           | "데이터는 안 보낸다" 원칙이 무너짐 | 버림     |
| **사용자가 만든 분류·태그 이름만 보냄** | 정확히 잡음    | 이름 문자열만 나감                 | **선택** |

보내는 것은 **이름 문자열뿐**입니다. 선택 칸에 직접 입력한 값과 태그, 각각 최대 50개, 몇 번 썼는지는 빼고. 금액도 메모도 날짜도 여전히 나가지 않습니다.

대신 사용자에게 숨기지 않기로 했습니다. 나키 화면에 이렇게 적혀 있습니다.

> 질문과 분류·태그 이름만 Google AI에 보내요

## 고르지 않은 것들

- **Claude·OpenAI**: API에 무료 등급이 없었습니다. **Groq(Llama)**: 무료지만 한국어 품질이 조금 떨어졌습니다. **OpenRouter 무료 모델**: 안정성이 들쭉날쭉했습니다. 결국 Gemini 무료 등급으로 정했습니다.
- **AI 업체 SDK 직접 호출**: 업체를 바꾸면 호출 코드가 다 바뀝니다. 여러 업체를 같은 모양으로 감싸 주는 라이브러리(Vercel AI SDK)를 쓰고, 조건 모양 검사도 거기 내장된 것을 썼습니다.
- **서버에서 찾고 계산하기**: 검색과 다른 조회 코드가 하나 더 생기고, 아직 서버에 안 올라간(오프라인에서 쓴) 기록이 빠져 "기록 탭에서 보기"와 건수가 어긋날 수 있습니다. 기기 안 사본에서 찾으면 둘이 항상 같습니다.
- **결과 전체 목록 보여 주기**: 질문을 몇 번 하면 대화 화면이 끝없이 길어집니다. 기록 3개만 보여 주고 "기록 탭에서 보기"로 넘깁니다.

## 같은 원칙으로 더한 것

- **두 기간 비교** "지난달보다 식비 많이 썼어?": AI는 비교할 두 기간만 조건으로 돌려주고, 합계와 차이는 기기에서 계산합니다. 진행 중인 달은 지난달의 **같은 날짜까지**와 견줍니다. 10월 27일이면 9월 1~27일입니다.
- **이어 묻기** "그럼 교통비는?" (#133): 바로 앞 질문 **한 개의 문장**과 서버가 걸러 둔 그 조건만 함께 보냅니다. 앞의 답(금액)과 기록은 보내지 않습니다.
- **대화 저장** (#135): 대화는 이 기기에만, 그것도 **조건 형태로만** 저장합니다. 답은 열 때마다 기기 사본에서 다시 계산합니다. 로그아웃하면 사본과 함께 지웁니다.

## 감수한 것

- **분류·태그 이름 자체가 민감할 수 있습니다.** 예를 들어 "병원"이라는 분류 이름은 그 자체로 정보입니다. 안내 문구로 알리고, 개인정보처리방침이 생기면 같은 문장을 넣기로 했습니다.
- **날짜 계산("지난달")을 AI에 맡깁니다.** 오늘 날짜와 주의 시작 요일을 지시문에 넣고, 받은 날짜는 유효한 날짜인지만 검사합니다.
- **lite 모델은 애매한 질문에 약할 수 있습니다.** 그래서 조건 칩이 있습니다. AI가 어떻게 이해했는지 사용자가 보고 바로잡을 수 있습니다.
- **무료 등급의 한도와 모델 이름이 자주 바뀝니다.** 모델 이름은 환경 변수로 빼고, 하루 횟수를 제한했습니다.

## 배운 것

- **"무엇을 보내는가"는 기능이 아니라 설계 결정이다.** 처음에 선을 그어 두지 않았다면 정확도를 올릴 때마다 조금씩 더 보냈을 것입니다. 선이 있으니 "이름만"에서 멈출 수 있었습니다.
- **원칙을 지키면서 정확도를 올리는 길은 보통 "더 보내기"가 아니라 "덜 믿기"다.** 조건 검사, 기기에서 계산, 조건 칩으로 확인. 셋 다 AI를 덜 믿는 장치이고, 그 덕에 AI에 보내는 것을 늘리지 않아도 됐습니다.
- **같은 길로 찾으면 설명이 쉬워진다.** 나키와 검색이 같은 코드로 기록을 찾으니 "나키 답과 검색 결과가 왜 다르죠?"라는 질문이 생기지 않습니다.

## 다시 한다면

첫 버전을 만들기 전에 "사용자가 직접 만든 이름을 AI가 모른다"는 상황을 미리 떠올렸을 것입니다. 기본 선택지만 보내는 설계는 사용자가 아무것도 안 만든 계정에서만 잘 돌아갑니다. 실제 사용자는 첫 주에 자기만의 분류를 만듭니다. 테스트 계정에 "Ott"와 "회사" 같은 이름이 처음부터 있었다면, 추가 결정을 한 번 더 하는 대신 처음부터 그 선에서 시작했을 것입니다.
